# Kimi Code CLI upstream findings

Inspected on 2026-09-18. This is source research, not a live authenticated integration test. The target is `MoonshotAI/kimi-code` at commit [`f233f9de04d71c42d27df870b18e1bc1a6605f16`](https://github.com/MoonshotAI/kimi-code/commit/f233f9de04d71c42d27df870b18e1bc1a6605f16). Its CLI package declares version `2.0.0`; that identifies the checked source, not a verified published release. See [package manifest](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/apps/kimi-code/package.json).

## Recommended interface

Use `kimi acp`. It exposes JSON-RPC over stdin/stdout with logs on stderr. The official reference documents session creation, load with history replay, resume without replay, list, fork, close, delete, prompt and cancellation. Initialization advertises capabilities and authentication methods. This fits an existing ACP Driver substantially better than introducing another transport. See [ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-acp.md).

The legacy Python repository explicitly directs new users to Kimi Code and says it will gradually wind down. Its `--wire` protocol must not be treated as a Kimi Code CLI contract. The successor's command reference documents `kimi -p ... --output-format stream-json` for noninteractive use; its JSONL omits thinking output. No public `--wire` entry point was found in the successor command reference or CLI source. ACP is the documented integration path. See [legacy transition notice](https://github.com/MoonshotAI/kimi-cli/blob/86f136422a0aae6b217ea49e7ea1d2e8a1defcd2/README.md) and [successor command reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-command.md).

## Confirmed capabilities and constraints

| Area | Evidence and integration consequence |
| --- | --- |
| Resume and history | `session/load` replays updates before resolving; `session/resume` skips replay. Prefer resume when PolyCode owns the visible transcript. Fork ignores requested cwd, additional directories and MCP overrides with a warning. [ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-acp.md) |
| Models and thinking | Session config options expose model, thinking and mode. Thinking depends on the selected model: off/on or declared effort levels, with off removed for always-thinking models. Discover these values rather than hard-code them. [Config options](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/config-options.ts) |
| Modes | `default`, `plan`, `auto`, `yolo` map to engine plan and permission settings. Runtime switching calls the engine services; plan is not merely a UI label. Preserve the distinction between manual approvals, safe-operation auto approval and all-operation approval. [Modes](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/modes.ts), [session implementation](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/session.ts) |
| Questions | With `elicitation.form`, Kimi sends native forms supporting multiple questions and multiple selections. Without it, the permission bridge asks only the first question with a single selection. Neither mapping preserves the synthetic Other free-text option. Advertise form support only after implementing its schema and response types. [Question mapping](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/question.ts), [interaction bridge](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/interaction-bridge.ts) |
| Approvals | Agent requests use `session/request_permission` with supplied option IDs. Forward the actual choices and selected ID; a generic boolean loses distinctions. A failed permission RPC rejects the operation. [Approval mapping](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/approval.ts), [interaction bridge](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/interaction-bridge.ts) |
| Streaming | Emits assistant and thought chunks, tool creation/update/result, plans, config changes and available commands. Tool IDs include turn IDs. Partial tool content uses replacement semantics; started calls may upgrade a prior pending call. Preserve content, diffs, locations and raw arguments rather than relying on title text. [Event mapping](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/events-map.ts) |
| Usage | `usage_update.used` is current context token count and `size` is model context capacity. It is emitted asynchronously after the prompt settles, may be absent when the catalog has no matching model, and contains no cost. It is not cumulative input/output billing usage. [Session usage implementation](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/session.ts) |
| Failure reporting | Authentication failures reject the prompt via JSON-RPC. Other failed turns generally map to `end_turn`; a filtered response maps to `refusal`. Consequently, prompt completion alone cannot prove success. This needs a fixture or upstream fix before treating automated Runs as successful. [Turn-end mapping](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/events-map.ts), [prompt settlement](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/session.ts) |
| Cancellation | `session/cancel` interrupts the current turn; cancelling the prompt request follows the same path. Close performs best-effort teardown of the live session. Verify process-tree cleanup separately on each Runner. [ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-acp.md) |
| Attachments and delegated tools | Images and embedded text resources are supported, audio is not. Blob resources are dropped with a warning. Advertising client filesystem or terminal capabilities redirects those operations to client reverse RPC. Leave those capabilities off unless PolyCode implements them at the correct Project Location. [ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-acp.md) |
| MCP | Client-provided stdio, HTTP and SSE servers are supported; ACP-transport MCP entries are discarded. [ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-acp.md) |

## Installation, authentication and platform behavior

The official installer distributes a native binary without requiring Node.js; npm installation also exists under `@moonshot-ai/kimi-code`. Windows requires Git for Windows because the CLI uses Git Bash. `KIMI_SHELL_PATH` can name a custom `bash.exe`. Existing npm-only provider health and upgrade logic therefore needs explicit handling of installation method. `kimi upgrade` handles supported package-manager and native installations differently. See [README](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/README.md) and [upgrade reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-command.md).

Existing CLI credentials are reused by ACP. The terminal supports Kimi Code OAuth and Moonshot API-key setup; `kimi login` offers the device-code flow without entering the TUI. ACP `authenticate` validates the login method and usable token rather than supplying a complete UI login flow. A terminal-login action is a reasonable first integration. Authentication must exist where the CLI runs, including SSH or WSL. See [README](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/README.md), [login reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-command.md), and [ACP reference](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/docs/en/reference/kimi-acp.md).

## Unverified behavior and release gates

The inspected ACP Session subscribes to its main agent's turn, tool and thinking events, plus compaction and session metadata. It does not expose a dedicated detached-task lifecycle subscription in that implementation. This is evidence of a gap in the inspected adapter, not proof that all background work is invisible: tools may provide status through other updates. Test whether background shells and subagents outlive prompt completion, whether late output is delivered, and how cancellation/close affects them before enabling automatic worktree cleanup. See [Session subscriptions](https://github.com/MoonshotAI/kimi-code/blob/f233f9de04d71c42d27df870b18e1bc1a6605f16/packages/acp-server/src/session.ts).

No authenticated prompt, Windows launch, SSH/WSL execution, migration, published package compatibility or process-tree cancellation was exercised in this research. Validate these against a pinned released binary. Both generations expose a `kimi` executable and `kimi acp`; executable discovery alone cannot distinguish them. Use initialization identity and capabilities together with version diagnostics.
